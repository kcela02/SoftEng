4.1 SYSTEM IMPLEMENTATION
================================================================================

This section describes how the system was developed and deployed based on the 
design presented in Chapter III. It includes the programming languages, 
development tools, frameworks, and hardware or software environments used.


4.1.1 Development Environment and Tools
--------------------------------------------------------------------------------

The Predictive Sales & Restocking Dashboard was developed using a modern 
three-tier web application architecture as specified in Section 3.3 of Chapter III.

A. Hardware Environment
-----------------------
- Processor: Intel Core i5 (10th Generation or equivalent)
- RAM: 8GB DDR4
- Storage: 256GB SSD
- Internet Connection: Broadband (Wi-Fi / Wired LAN)

B. Software Environment
-----------------------
- Operating System: Windows 10/11 or macOS
- Web Browsers: Google Chrome, Mozilla Firefox, Microsoft Edge, Safari
- Python Version: 3.11.9
- Node.js Version: Not Required (server-side rendering via Jinja2)


4.1.2 Technology Stack
--------------------------------------------------------------------------------

The system was built using the following technologies:

| Component | Technology | Purpose |
|-----------|------------|---------|
| Frontend | Jinja2 HTML Templates + Chart.js | Server-side rendered UI and dashboard charts |
| Backend | Python (Flask) | Server-side logic and API |
| Database | PostgreSQL/SQLite | Data storage and retrieval |
| ORM | SQLAlchemy | Database management |
| Authentication | Flask-Login | User authentication |
| Data Processing | Pandas, NumPy | Data manipulation and analysis |
| Forecasting | statsmodels, scikit-learn | ARIMA and Linear Regression models |
| Visualization | Chart.js | Dashboard charts and graphs |


4.1.3 System Modules and Implementation
--------------------------------------------------------------------------------

The system consists of the following modules:

A. User Authentication Module
-----------------------------
This module handles user login and logout functionality. It uses Flask-Login 
to manage user sessions. The module supports two user roles: Admin and Staff.

Implementation Details:
- Admin has full access to all features including system settings
- Staff has limited access: can view forecasts, update inventory, receive alerts
- Passwords are securely hashed using Werkzeug PBKDF2-SHA256
- Account lockout is enforced after 5 consecutive failed login attempts for 15 minutes
- Rate limiting is applied: 200 requests/day and 50 requests/hour per IP address
- CSRF protection is enforced on all state-changing requests via Flask-WTF
- Session timeout is set to 2 hours of inactivity


B. CSV Data Upload Module
--------------------------
This module allows users to upload historical sales data in CSV format. 
The uploaded data is validated and cleaned before being stored in the database.

Implementation Details:
- Accepts .csv files only
- Validates column headers: date, product_name, quantity, price
- Handles missing values and duplicate records
- Maximum file size: 16MB
- File is validated for UTF-8 encoding to detect binary files disguised as CSV
- Upload status (rows processed, rows failed, rows skipped) is tracked in the ImportLog table
- Duplicate records are detected and skipped automatically


C. Data Validation and Cleaning Module
---------------------------------------
This module processes the raw CSV data to ensure quality and consistency.

Features:
- Date format validation and standardization
- Removal of duplicate records
- Handling of missing/null values
- Data type conversion
- Outlier detection

All data cleaning operations are performed using Pandas. Missing values are forward-filled or removed depending on the field type. Dates are parsed and standardized to YYYY-MM-DD format before storage. Outliers are identified via statistical thresholds and flagged for review.


D. Forecasting Engine Module
----------------------------
This module implements the predictive analytics using two models:

1. Linear Regression (Baseline Model)
   - Purpose: Identify long-term sales trends
   - Library: scikit-learn
   - Output: Trend direction (increasing/decreasing)

2. ARIMA (Primary Model)
   - Purpose: Capture seasonality, trends, and autocorrelation
   - Library: statsmodels
   - Parameters: Auto-determined (p, d, q)
   - Output: Predicted demand for future periods

The ARIMA model automatically selects the best (p, d, q) order from candidates (1,1,1), (2,1,2), (5,1,0), and (2,0,2) using the Akaike Information Criterion (AIC). A minimum of 30 days of historical data is required for ARIMA, and a minimum of 5 days for Linear Regression. Three forecast horizons are generated per product: 1-day, 7-day, and 30-day. The Linear Regression model applies exponential sample weighting so that recent sales data is given more influence during training.


E. Dashboard Visualization Module
----------------------------------
This module displays the analytical results in an intuitive, visual format.

Features:
- Sales trend charts (line graphs)
- Forecast visualization
- Inventory status indicators
- Restock alert notifications
- Interactive filters and date ranges

The dashboard is rendered server-side using Jinja2 templates and uses Chart.js for interactive visualizations. Metric counters animate from zero to their final value on page load. The historical performance chart supports toggling between monthly bar view and daily trend view. Pre-set filter periods (7d, 30d, 3m, 6m, 1y, all) and a custom date range picker allow users to slice the data.


F. Inventory Management Module
--------------------------------
This module tracks current stock levels and manages product information.

Features:
- Add/Edit/Delete products
- Set reorder levels per product
- Track stock movements
- Real-time inventory updates

Products are tracked with an InventoryBatch model that supports FIFO batch management and expiration dates. Each batch has an urgency level: OK (>14 days), MEDIUM (≤14 days), HIGH (≤7 days), CRITICAL (≤3 days), or EXPIRED. A BatchTransaction table provides a full audit trail for all inventory movements (sales, adjustments, receipts).


G. Restock Alert System Module
-------------------------------
This module automatically generates alerts when stock falls below reorder level.

Features:
- Automatic triggering when current_stock < reorder_level
- Alert status tracking (pending/resolved)
- Notification display on dashboard
- Alert history logging

The alert system uses multi-horizon forecasts to assign a severity level: CRITICAL when current stock is below the 1-day forecasted demand, HIGH when below the 7-day forecast, and MEDIUM when below the 30-day forecast. Each alert includes a recommended order quantity calculated with a 20% safety margin. If an existing active and unacknowledged alert already exists for a product, the system updates the severity only if it has worsened, avoiding duplicate alert spam.


4.1.4 Integration and Deployment
--------------------------------------------------------------------------------

The frontend and backend communicate via RESTful API endpoints:

| Endpoint | Method | Description |
|----------|--------|-------------|
| /api/login | POST | User authentication |
| /api/upload | POST | CSV file upload |
| /api/products | GET/POST | List/Add products |
| /api/forecast | GET | Get forecast results |
| /api/alerts | GET | Get restock alerts |
| /api/inventory | GET/PUT | Get/Update inventory |

The system was deployed on Render, a cloud hosting platform. The application is served by Gunicorn with 4 worker threads. The database uses PostgreSQL (provided by Render's managed database service). The deployment is configured via render.yaml for automated CI/CD builds. The Python runtime used is Python 3.11.9.
